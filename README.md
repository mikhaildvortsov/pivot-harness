# Pivot — харнес для pi: автономная работа на дешёвых моделях, Opus только там, где он нужен

Pivot — это настроенный конфиг агента [pi](https://pi.dev) (`@earendil-works/pi-coding-agent`): модели, маршрутизация, защиты, воркфлоу задачи и терминальный интерфейс. Цель: агент берёт задачу, сам доводит её до проверенной ветки и черновика PR, почти не спрашивает разрешений, а платите вы за это копейки.

- Основную работу (код, тесты, отладка) делают дешёвые открытые модели через NanoGPT и резерв Gonka.
- Claude по подписке Anthropic подключается точечно: спецификации, финальное ревью, совет при затыке.
- Агент никогда не мерджит сам, не пушит в `main`, не делает force-push и не трогает конфиг самого харнеса.

> Проверено только на macOS. Раздел про Windows составлен по документации pi и содержимому репозитория, на реальной Windows-машине не запускался. Что именно не проверено, указано в конце.

## Модели и подписки

### Anthropic (подписка, без API-ключа)
Подключается командой `/login` внутри pi (OAuth, вход через браузер). Расход идёт из лимитов вашего плана Claude, отдельно за токены вы не платите. Какой именно план нужен и сколько он стоит, решайте сами: цены и лимиты подписок меняются, здесь их нет. Харнес зовёт Claude редко и только по ролям:

| Роль | Модель |
|---|---|
| Спецификации, требования, speckit | Opus 5.5 (для задач по безопасности Opus 4.8) |
| Финальное ревью перед «готово» | Opus 5.5 (безопасность: Opus 4.8) |
| Совет, когда модель застряла (инструмент `ask_opus`) | Opus 5.5 |
| Проверка классификации задачи | Sonnet 5.5, thinking medium |

Без подписки харнес работает на открытых моделях, но спецификации, ревью и проверка классификации (см. воркфлоу) теряют Claude. Как они тогда себя ведут, я не проверял.

### Открытые модели: виртуальная модель `router/auto`
В `/model` видны только `router/auto` и модели Anthropic. Физическую модель выбирает роутер (`ext/router.ts`) и переключается по цепочке при сбоях.

Текст: NanoGPT DeepSeek V4.1 Flash 1017, закреплённый на провайдере Runware → тот же DeepSeek с автовыбором провайдера → NanoGPT Qwen3 Coder Next → Gonka GLM-5.3 Flash → Gonka DeepSeek V4 Flash.
Картинки: NanoGPT GLM-5.3 Flash → Gonka GLM-5.3 Flash.
Уровень thinking pi `off` даёт обычный DeepSeek, любой другой (по умолчанию `high`) даёт вариант `:thinking`.

| Модель | Где | Вход / выход / кэш, $ за 1M токенов | Для чего |
|---|---|---|---|
| DeepSeek V4.1 Flash 1017 | NanoGPT | 0,10 / 0,60 / 0,0042 | реализация, отладка, тесты, рутина |
| GLM-5.3 Flash | NanoGPT, Gonka | 0,10 / 0,30 / — | картинки и UI по скриншотам |
| Qwen3 Coder Next | NanoGPT | 0,12 / 0,80 / 0,07 | запасной для кода |
| DeepSeek V4 Pro 0813 | NanoGPT | 0,66 / 2,50 / 0,04 | не включена: в 5-6 раз дороже, нужна только если на ваших задачах выигрывает |
| GLM-5.3 полная | NanoGPT | 0,60 / 1,10 / 0,20 | редко: сложное планирование без Anthropic |

Цены и замеры скорости сняты автором 2026-11-24 на NanoGPT. Независимых бенчмарков мало, часть цифр вендорские. На 10-20 своих задачах стоит перемерить, какую долю результатов вы принимаете. Подробности: `MODELS.md`.

### Ключи
Хранятся в переменных окружения, в репозиторий не попадают:

| Переменная | Сервис | Зачем |
|---|---|---|
| `NANOGPT_API_KEY` | [nano-gpt.com](https://nano-gpt.com) | основные модели. Баланс пополняется отдельно: минимум $0,10, держать $5-10 |
| `GONKA_API_KEY` | Gonka | резерв, когда NanoGPT недоступен или баланс кончился |

Без `GONKA_API_KEY` резерва нет: как роутер ведёт себя тогда, я не проверял.

Отказы и резерв:
- Таймаут, 5xx, 429: один повтор в той же модели, затем модель на 10 минут уходит в сторону, берётся следующая.
- 401/402/403 или пустой баланс NanoGPT: роутер на час переводит работу на Gonka.
- Баланс NanoGPT проверяется при старте и раз в 30 минут: меньше $0,50 предупреждение, меньше $0,02 переход на Gonka.

## Установка на Windows

Нужны: Windows 10/11, [Node.js](https://nodejs.org) 22.19 или новее, [Git for Windows](https://git-scm.com/download/win) (pi запускает команды через Git Bash), Windows Terminal (поддерживает truecolor). Команды ниже для PowerShell.

**1. Установить pi**
```powershell
powershell -c "irm https://pi.dev/install.ps1 | iex"
```
или через npm:
```powershell
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

**2. Положить харнес в `%USERPROFILE%\.pi\agent`.** Именно туда: в `settings.json` есть пути вида `~/.pi/agent/ext/...`. Если pi уже запускался и папка существует, сначала уберите её в сторону:
```powershell
if (Test-Path "$env:USERPROFILE\.pi\agent") { Rename-Item "$env:USERPROFILE\.pi\agent" "agent.old" }
git clone https://github.com/mikhaildvortsov/pivot-harness "$env:USERPROFILE\.pi\agent"
```
Репозиторий закрытый: владелец должен добавить вас в Collaborators, а `git clone` попросит войти в GitHub.

**3. Добавить `bin` в PATH** (один раз, потом откройте новый терминал):
```powershell
$bin = "$env:USERPROFILE\.pi\agent\bin"
$user = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$user;$bin", "User")
```

**4. Ключи** (потом тоже новый терминал):
```powershell
setx NANOGPT_API_KEY "ваш_ключ_nanogpt"
setx GONKA_API_KEY "ваш_ключ_gonka"
```

**5. Подписка Anthropic:** запустите `pivot`, введите `/login`, выберите Anthropic и войдите в браузере.

**6. Проверка:** внутри pivot выполните `!printf 'Bash is working\n'`. Если pi не нашёл Bash, поставьте Git for Windows или укажите `shellPath` в `settings.json`. Затем `/doctor` прогонит диагностику моделей, защит и конфига (2-4 минуты).

При первом запуске pi сам скачает пакеты из `settings.json`: `cc-safety-net`, `superpowers`, `pi-subagents`. Нужны интернет и Git.

Необязательные зависимости от Claude Code: в `settings.json` подключены скиллы `~/.claude/skills/speckit-*`, а `skill-router` и `project-memory` читают каталоги Claude Code. Если Claude Code у вас не стоит, этих скиллов и памяти не будет. Как расширения поведут себя без них, я не проверял. При ошибках отключите их в списке `extensions` в `settings.json`.

Запуск Bash-скриптов из `bin` (`pivot`, `pivot-start`, `install`) на Windows не нужен: на Windows работает `bin\pivot.cmd`.

## Запуск

```powershell
cd путь\к\проекту
pivot
```
`bin\pivot.cmd` выставляет `PI_CODING_AGENT_DIR` на этот харнес и запускает `pi`. Пока вы ничего не ввели, на экране заставка. Первый символ ввода убирает её.

Задачу просто пишите словами. Агент сам её классифицирует, спланирует и выполнит.

## Команды и клавиши

### Самописные команды
| Команда | Что делает |
|---|---|
| `/palette` | палитра: панели, команды, skills, темы |
| `/sessions` | панель чатов: переключение, новый, переименование, поиск по всем проектам |
| `/subagents` | панель подагентов: запуски, этапы, агенты, статус каждого |
| `/checks` | панель проверок текущей задачи (✓/✗: типы, линтер, ревью, защиты) |
| `/gradient` | выбор градиента заставки, заголовка и строки «Vibing...» (aurora, ocean, ember, neon, mauve) |
| `/doctor` | диагностика харнеса сейчас (2-4 минуты), отчёт в `state/diagnostics/` |
| `/journal [n]` | последние `n` задач из журнала: исход, время, стоимость, модели |
| `/problem текст` | записать в журнал, что пошло не так в последней задаче |
| `/exit` | выйти в терминал |
| `/tab` | новая вкладка с чатом (только Ghostty на macOS) |

Встроенные `/resume`, `/new`, `/name` перенаправлены на панели харнеса. Свои клавиши можно поставить в `state/ui-keys.json`.

### Клавиши на Windows
| Действие | Клавиши |
|---|---|
| Панель чатов | `Ctrl+R` |
| Панель подагентов | `Ctrl+F` |
| Панель проверок | `Ctrl+B` |
| Палитра команд | `Ctrl+Y` или `F1` |
| Вставка картинки из буфера | `Ctrl+V` |

На macOS клавиши другие (`Ctrl+R` и `⌘⇧E` и так далее), список в `UI.md`. Профили лежат в `ui-keys.json`.

### Инструменты для модели (в чате их вызывает агент)
`classify_task` (классификация новой задачи), `ask_opus` (совет Opus), `find_skills` (подбор скиллов из больших библиотек), `subagent` (подагент из пакета pi-subagents).

### Скиллы харнеса
`critic` (независимый аудит изменений перед сдачей), `fullstack-plan` (контракт backend↔frontend перед кодом), `ship-pr` (ветка, rebase, push, черновик PR, проверка CI).

## Воркфлоу одной задачи

1. **Классификация.** Первым делом агент вызывает `classify_task`: вопрос, спецификация, код, отладка, ревью, документация; затронуты ли безопасность и обе стороны (backend и frontend); сколько подзадач. Пока задача не классифицирована, писать файлы нельзя. Классификацию проверяет Sonnet 5.5: его вердикт главный, а флаг безопасности включается, если его поставил любой из двух.
2. **Спецификация (`spec`).** Дальше ведёт Opus и пишет только документы, не код. Режим `materials` пишет спеку строго по вашим материалам, `speckit` через spec-kit с нуля.
3. **Фулстек.** Сначала контракт (DTO, схемы, коды ошибок) в `.pi/context/plan.md`, потом backend и frontend строго по нему. На backend проверка прав на каждый объект и роль, на frontend состояния загрузки, ошибки, пустоты и успеха.
4. **Подагенты.** Если в плане больше трёх подзадач, писать код самому нельзя, пока не вызван `subagent`: по одному `worker` на подзадачу и `reviewer` после. Каждый подагент в начале выбирает и читает 2 подходящих скилла из библиотек.
5. **Автопроверка.** Перед завершением, если изменилось дерево git, запускаются типы и линтер для определённого стека. При ошибке вывод возвращается агенту, до двух попыток.
6. **Критик.** Для нетривиальных изменений скилл `critic` делает независимый аудит диффа.
7. **Ревью Opus.** Для крупных или связанных с безопасностью изменений read-only ревью Opus (до двух раундов), BLOCKER возвращается исполнителю.
8. **Сдача.** Ветка задачи, rebase на свежую базу, push, черновик PR, проверка SHA на удалённой стороне и статус CI. Агент спрашивает «Мерджить PR #N?» и мерджит только если вы явно ответили да.

«Готово» означает проверено: агент обязан показать точные команды и коды возврата, а пропущенные проверки назвать прямо.

## Защиты и правила

Из `AGENTS.md` (читается агентом в каждой задаче):
- Решает сам и не спрашивает: разрешений на команды, правки и запуск подагентов не просит. Спрашивает только про необратимое, безопасность, деньги и неоднозначные продуктовые решения.
- Без заглушек: `TODO`, `FIXME`, пустой `catch {}`, `as any`, `@ts-ignore` запрещены, тесты и линтер не ослабляются и не удаляются.
- Бюджет вывода 16384 токена: правки точечными `edit`, чтение только нужных диапазонов, независимые вызовы одним ходом.
- Git: только явные пути в `git add`, без `--no-verify`, без force-push, без push в `main`/`master`, без самостоятельного мерджа; никаких подписей AI и co-author в коммитах.
- Секреты: `.env*` не читаются и не печатаются.

Расширения-защиты (`ext/`):

| Расширение | Что делает |
|---|---|
| `anti-laziness` | блокирует запись заглушек и обходов типов/линтера |
| `config-guard` | агент не может менять сам харнес (`settings`, `models`, расширения, скиллы) |
| `git-guard` | жёсткие правила git/GitHub: без force-push и push в базовую ветку, мердж только по вашей явной просьбе |
| `swarm-gate` | обязательные подагенты для больших планов |
| `task-classifier` | классификация и блок записи до неё |
| `auto-verify`, `ship-gate`, `flow-skills` | автопроверка, критик, сдача PR |
| `opus-director` | Opus как директор спецификаций и ревьюер, но не основной кодер |
| `nanogpt-guard`, `router`, `stream-watchdog` | отказоустойчивость провайдеров: таймауты, повторы, резерв, борьба с «зависшими» потоками Gonka |
| `journal`, `self-check`, `watchdog-maintainer` | журнал, диагностика после обновлений pi, самолечение watchdog |

Пакет `cc-safety-net` дополнительно блокирует опасные команды.

## Экономика на месяц

Исходные данные: средняя задача ≈ 650k входных токенов (около 90% из кэша) и 40k выходных. Цены из таблицы выше.

| Модель | Цена одной такой задачи |
|---|---|
| DeepSeek V4.1 Flash 1017 (основная) | ≈ $0,033 |
| GLM-5.3 Flash | до $0,08 |
| Qwen3 Coder Next | ≈ $0,08 |
| DeepSeek V4 Pro (не включена) | ≈ $0,17 |

Средняя задача с запасом на подагентов, `critic` и повторы: **$0,05–0,08**.

| Нагрузка в месяц | NanoGPT |
|---|---|
| 20 задач | $1–2 |
| 60 задач | $2,5–5 |
| 150 задач | $6–12 |

Anthropic идёт по подписке: фиксированная цена плана без доплаты за токены, но Opus и Sonnet расходуют лимиты плана. Харнес зовёт их только на спецификацию, ревью, совет и проверку классификации, а не на каждый шаг.

Практика: держите на балансе NanoGPT $5–10 и пополняйте, когда остаток меньше $3. Оценка сделана по замерам, а не по реальному месяцу работы: после 2–3 недель сверьте с `/journal` (там реальная стоимость каждой задачи по ценам из `models.json`). Тяжёлые режимы (подагенты, `max` thinking, V4 Pro) увеличивают расход в разы.

## Журнал, диагностика, обновления

- Журнал `journal/journal.jsonl`: одна строка на задачу (классификация, модели, токены, стоимость, длительность, ошибки, активность защит, PR, исход). `/problem` добавляет заметку. Журнал локальный и в репозиторий не попадает.
- `/doctor` и автоматическая диагностика после обновления pi (в фоне, отчёт в `state/diagnostics/`).
- Обновление pi: `pi update`. Расширение `watchdog-maintainer` после обновления проверяет `stream-watchdog` и при поломке запускает Opus в фоне, чтобы починить только его.
- Обновление харнеса: `git pull` в `%USERPROFILE%\.pi\agent`.

## Только для macOS и непроверенное

Работает только на macOS: режим вкладок Ghostty (`/tab`, переключение чатов по вкладкам, шейдерный фон, конфиг в `ghostty/`), стартовый выбор папки через yazi (`bin/pivot-start`, `--pick`), клавиши `⌘`. На Windows их нет: чат, панели, заставка, футер с токенами, балансом и стоимостью, градиенты и все расширения-защиты работают в обычном терминале.

Не проверялось:
- запуск на Windows целиком (`pivot.cmd`, установка пакетов, Git Bash, PATH, `setx`);
- поведение без Claude Code (`skill-router`, `project-memory`, скиллы speckit) и без подписки Anthropic;
- поведение роутера без `GONKA_API_KEY`;
- качество работы моделей на реальных больших задачах: замеры скорости и ошибок сняты на синтетических запросах;
- реальный мердж PR командой агента.

## Что лежит в репозитории

```
settings.json       пакеты, расширения, thinking, subagents
models.json         провайдеры NanoGPT и Gonka и цены (ключи только из переменных окружения)
AGENTS.md           правила агента
MODELS.md           кто за что отвечает, цены, расход
UI.md               справочник по интерфейсу, клавишам, Ghostty и yazi
ui-keys.json        клавиши по системам; keybindings.json
ext/                расширения: роутинг, защиты, воркфлоу, интерфейс
extensions/subagent настройки подагентов
skills/             critic, fullstack-plan, ship-pr
themes/             цветовые темы
bin/                запуск: pivot.cmd (Windows), pivot (macOS/Linux)
ghostty/, yazi/     только macOS
doctor/             скрипт диагностики
```
Не попадают в репозиторий: `auth.json` (токены входа), `sessions/`, `state/`, `local/`, `journal/`, `trust.json`, `models-store.json`.

# Pivot — автономный агент для разработки: дешёвые модели делают работу, Opus подключается только там, где он нужен

Pivot — это настроенный агент для работы с кодом в терминале: модели, маршрутизация, защиты, воркфлоу задачи и терминальный интерфейс. Цель: агент берёт задачу, сам доводит её до проверенной ветки и черновика PR, почти не спрашивает разрешений, а платите вы за это копейки.

- Основную работу (код, тесты, отладка) делают дешёвые открытые модели через NanoGPT и резерв Gonka.
- Claude по подписке Anthropic подключается точечно: спецификации, финальное ревью, совет при затыке, проверка классификации задачи.
- Агент никогда не мерджит сам, не пушит в `main`, не делает force-push и не трогает конфиг самого харнеса.
- Работает в обычном терминале, в том числе во встроенном терминале VS Code.

> Автор проверял харнес только на macOS. Раздел про Windows составлен по документации используемого ядра и содержимому репозитория, на реальной Windows-машине не запускался. Что именно не проверено, указано в конце.

## Модели и подписки

### Anthropic (подписка, без API-ключа)
Подключается командой `/login` внутри Pivot (OAuth, вход через браузер). Расход идёт из лимитов вашего плана Claude, отдельно за токены вы не платите. Какой именно план нужен и сколько он стоит, решайте сами: цены и лимиты подписок меняются, здесь их нет. В `/model` доступны три модели Anthropic: Opus 5.5, Opus 4.8 и Sonnet 5.5. Харнес зовёт их редко и только по ролям:

| Роль | Модель |
|---|---|
| Спецификации, требования, speckit | Opus 5.5 (для задач по безопасности Opus 4.8) |
| Финальное ревью перед «готово» | Opus 5.5 (безопасность: Opus 4.8) |
| Совет, когда модель застряла (инструмент `ask_opus`, не больше 3 раз за задачу) | Opus 5.5 |
| Проверка классификации задачи (таймаут 90 с) | Sonnet 5.5, thinking medium |

Opus никогда не пишет код: на спецификациях он правит только документы (`.md`, `specs/`, `docs/`, `.specify/`), на ревью только читает. Код пишут открытые модели.

Без подписки харнес работает на открытых моделях, но спецификации, ревью и проверка классификации теряют Claude. Как они тогда себя ведут, я не проверял.

### Открытые модели: виртуальная модель `router/auto`
В `/model` видны только `router/auto` и модели Anthropic (`enabledModels` в `settings.json`). Физическую модель выбирает роутер (`ext/router.ts`) и переключается по цепочке при сбоях. Полный список физических моделей: `pivot --list-models`.

- Текст: NanoGPT DeepSeek V4.1 Flash 1017, закреплённый на провайдере Runware → тот же DeepSeek с автовыбором провайдера → NanoGPT Qwen3 Coder Next → Gonka GLM-5.3 Flash → Gonka DeepSeek V4 Flash.
- Картинки: NanoGPT GLM-5.3 Flash → Gonka GLM-5.3 Flash.
- Уровень thinking `off` даёт обычный DeepSeek, любой другой (по умолчанию `high`) даёт вариант `:thinking`.
- GLM на Gonka всегда без thinking: в режиме рассуждения он печатает вызов инструмента сырым текстом.

| Модель | Где | Вход / выход / кэш, $ за 1M токенов | Для чего | Замер (NanoGPT) |
|---|---|---|---|---|
| DeepSeek V4.1 Flash 1017 | NanoGPT | 0,10 / 0,60 / 0,0042 | реализация, отладка, тесты, рутина | 114-144 ток/с, ответ 4,5-7 с, 0 ошибок из 12 |
| GLM-5.3 Flash | NanoGPT, Gonka | 0,10 / 0,30 / — | картинки и UI по скриншотам | 62 ток/с, первый токен до 13 с |
| Qwen3 Coder Next | NanoGPT | 0,12 / 0,80 / 0,07 | запасной для кода | 70 ток/с, 0 ошибок |
| DeepSeek V4 Pro 0813 | NanoGPT | 0,66 / 2,50 / 0,04 | не включена: в 5-6 раз дороже, нужна, только если на ваших задачах выигрывает | 97 ток/с |
| GLM-5.3 полная | NanoGPT | 0,60 / 1,10 / 0,20 | редко: сложное планирование без Anthropic (`max`, до 87 с до первого токена) | не мерили |

Цены и замеры скорости сняты автором 2026-11-24 на NanoGPT. Независимых бенчмарков мало, часть цифр вендорские. На 10-20 своих задачах стоит перемерить, какую долю результатов вы принимаете. Подробности: `MODELS.md`.

### Ключи
Хранятся в переменных окружения, в репозиторий не попадают:

| Переменная | Сервис | Зачем |
|---|---|---|
| `NANOGPT_API_KEY` | [nano-gpt.com](https://nano-gpt.com) | основные модели. Баланс пополняется отдельно: минимум $0,10, держать $5-10 |

## Установка одной командой

Скрипт сам проверит Git и Node.js 22.19+, поставит ядро Pivot, если его нет, положит харнес в папку `%USERPROFILE%\.pi\agent` (macOS и Linux: `~/.pi/agent`) и добавит команду `pivot` в PATH. **Ключи он не трогает и не спрашивает**: их вы добавляете сами (ниже). Старая папка, если она была, переносится в `agent.bak-<дата>` (ничего не удаляется), а ваши входы и история чатов копируются в новую. Повторный запуск скрипта обновляет харнес.

Нужен [Git for Windows](https://git-scm.com/download/win) (Pivot запускает команды через Git Bash) и [Node.js](https://nodejs.org) 22.19 или новее.

**Windows (PowerShell):**
```powershell
git clone https://github.com/mikhaildvortsov/pivot-harness "$env:TEMP\pivot-install"; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\pivot-install\install.ps1"
```

**macOS и Linux:**
```sh
git clone https://github.com/mikhaildvortsov/pivot-harness /tmp/pivot-install && sh /tmp/pivot-install/install.sh
```

Репозиторий закрытый: владелец должен добавить вас в Collaborators, а `git clone` попросит войти в GitHub. Если репозиторий станет публичным, хватит одной строки без клонирования:
```powershell
irm https://raw.githubusercontent.com/mikhaildvortsov/pivot-harness/main/install.ps1 | iex
```
```sh
curl -fsSL https://raw.githubusercontent.com/mikhaildvortsov/pivot-harness/main/install.sh | sh
```

После установки откройте **новый** терминал и добавьте свои ключи:
```powershell
setx NANOGPT_API_KEY "ваш_ключ_nanogpt"
setx GONKA_API_KEY "ваш_ключ_gonka"
```
(macOS и Linux: строки `export NANOGPT_API_KEY="..."` в `~/.zshrc` или `~/.profile`.) Подписка Anthropic: запустите `pivot` и введите `/login`.

**Проверка:** внутри Pivot выполните `!printf 'Bash is working\n'`. Если Pivot не нашёл Bash, поставьте Git for Windows или укажите `shellPath` в `settings.json`. Затем `/doctor` прогонит диагностику моделей, защит и конфига (2-4 минуты).

При первом запуске Pivot сам скачает пакеты из `settings.json`: `cc-safety-net` (блокировка опасных команд), `superpowers` v7.0.2 (процессные скиллы: brainstorming, writing-plans, TDD, verification) и пакет подагентов 0.90.0. Нужны интернет и Git.

Папка `.pi` в пути установки не случайна: пути в `settings.json` и расширениях ссылаются на неё, поэтому харнес нужно держать именно там.

Необязательные зависимости от Claude Code: в `settings.json` подключены скиллы `~/.claude/skills/speckit-*`, а `skill-router` (библиотеки aas и ecc, около 2600 скиллов) и `project-memory` читают каталоги Claude Code. Если Claude Code у вас не стоит, этих скиллов и памяти не будет. Как расширения поведут себя без них, я не проверял. При ошибках отключите их в списке `extensions` в `settings.json`.

Windows-оболочка: на Windows работает `bin\pivot.cmd`. Bash-скрипты `bin/pivot`, `bin/pivot-start`, `bin/install` относятся к macOS и Linux. Проверки внутри харнеса используют `git`, `shasum`, `xargs`: им нужен Git Bash или WSL.

## Запуск

```powershell
cd путь\к\проекту
pivot
```
`pivot` запускает агента с этим харнесом как конфигом из любой папки проекта. Пока вы ничего не ввели, на экране заставка. Первый символ ввода убирает её насовсем; вернуть: команда `/splash`. Выключить заставку: переменная окружения `PIVOT_NO_SPLASH=1`.

Задачу просто пишите словами. Агент сам её классифицирует, спланирует и выполнит.

## Интерфейс в обычном терминале

Всё ниже работает в любом терминале с truecolor, включая встроенный терминал VS Code. Файлы: `ext/ui-*.ts`, общие примитивы в `ext/lib/ui-kit.ts` и `ext/lib/panel.ts`. Справочник: `UI.md`.

**Заставка.** Пока чат пуст и ввод не начат, на весь терминал: падающий дождь из цифр числа π, из пустоты проявляется пиксельная π и крутится как монета, затем блочная надпись PIVOT с вспышкой и тенью. Цвет один, акцентный. Любая набранная буква убирает заставку и показывает шапку; стирание текста её не возвращает, повторно она показывается командой `/splash`.

**Шапка задачи** («π pivot» и версия): название чата или краткая суть задачи, плашки класса задачи (вопрос, спецификация, разработка, отладка, ревью, документация, операции), `fullstack`, `security`, `spec:режим`, `один агент` или `подагенты ×N`, номер и статус PR (draft/merged). Под шапкой линия, по которой пробегает свет, пока агент работает.

**Подвал**:
- модель маршрута (какую физическую модель роутер выбрал сейчас);
- заполненность контекста, но только когда она 60% и больше («контекст N%»);
- токены входа и выхода, скорость токенов в секунду с мини-графиком;
- стоимость задачи и сессии, включая подагентов, по ценам из `models.json`;
- остаток баланса NanoGPT;
- цветные огни здоровья провайдеров: Runware, NanoGPT, Gonka, Anthropic (зелёный, жёлтый или красный по недавним ошибкам и активной проверке через 3,5 секунды после старта; у NanoGPT и Runware красный при пустом балансе);
- ветка git показывается, только если она настоящая (не `detached`).

**Строка «Vibing...»** прямо над полем ввода слева: пиксельный спиннер, мерцающее слово, время и текущее действие агента («читаю», «правлю», «запускаю», «ищу», «классифицирую», «советуюсь с Opus» и имя цели). Встроенная строка загрузки pi скрыта. Размышления моделей в ленту не выводятся (`hideThinkingBlock`).

**Поле ввода.** Рамка вокруг него спокойная акцентная линия, а пока агент работает, по ней бежит яркая «комета» с затухающим хвостом. Каждая набранная буква на мгновение рисуется приглушённой (45 мс) и затем в полную яркость. Восстановленная из истории строка ставит курсор в конец.

**Вызовы инструментов** в ленте идут с анимированными заголовками: что именно делает агент, с какими файлами и командами.

**Панели** (открываются клавишей или командой, `Esc` закрывает):
- **Чаты** (`/sessions`): список сессий с поиском, переключение, новый чат (`^N`), переименование (`^R`), переключение «все проекты» (`^A`). Стоимость там не показывается.
- **Подагенты** (`/subagents`): запуск → этап → агент, галочки и крестики, скелетон-анимация у работающих, внутри агента виден ход его работы. Над редактором при работе подагентов виден виджет с линией потока.
- **Проверки** (`/checks`): всё, что проверяет или блокирует агента в текущей задаче: типы и линтер, `critic`, ревью Opus, сработавшие защиты. ✓/✗, длительность, подробности по Enter. Краткая сводка (`✓3 ✗1`) в подвале.
- **Палитра** (`/palette`): все панели, команды, скиллы и темы в одном списке с поиском.

**Стиль.** Один акцентный цвет (`ext/lib/accent.ts`), без градиентов. Движение даёт яркость и позиция: комета бежит по рамке ввода, пока агент работает, «Vibing...» дышит, заставка статична.

**Эффекты.** Системное уведомление, если задача шла дольше `notifyAfterSec` (по умолчанию 30 секунд). Настройки в `state/ui-effects.json`: `{ "notifyAfterSec": 30, "osc": false }`.

**Встроенные команды.** `/resume`, `/new`, `/name` остаются в меню и открывают замену: панель чатов, новый чат и переименование. `/exit` выходит в терминал.

**Цвета и темы.** В репозитории 25 цветовых тем (`themes/`): Catppuccin, Gruvbox, Dracula, Atom One, MacBook Neo. Выбираются в палитре.

## Команды и клавиши

### Самописные команды
| Команда | Что делает |
|---|---|
| `/palette` | палитра: панели, команды, skills, темы |
| `/sessions` | панель чатов |
| `/subagents` | панель подагентов |
| `/checks` | панель проверок текущей задачи |
| `/splash` | показать заставку (любая клавиша скрывает) |
| `/doctor` | диагностика харнеса сейчас (2-4 минуты), отчёт в `state/diagnostics/` |
| `/journal [n]` | последние `n` задач из журнала (по умолчанию 8, максимум 30): исход, время, стоимость, модели |
| `/problem текст` | записать в журнал, что пошло не так в последней задаче |
| `/exit` | выйти в терминал |
| `/opus` или начать сообщение с `опус:` | заставить Opus вести эту задачу |

### Клавиши на Windows
| Действие | Клавиши |
|---|---|
| Панель чатов | `Ctrl+R` |
| Панель подагентов | `Ctrl+F` |
| Панель проверок | `Ctrl+B` |
| Палитра команд | `Ctrl+Y` или `F1` |
| Вставка картинки из буфера | `Ctrl+V` |

`keybindings.json` освобождает `Ctrl+B/F/Y/R`, занятые встроенными командами (стрелки влево и вправо остаются; yank на `Ctrl+Shift+Y`, переименование в списке сессий на `Ctrl+Shift+R`).

Клавиши во встроенном терминале VS Code могут перехватываться самим VS Code (например, `F1` открывает палитру VS Code, `Ctrl+F` поиск в терминале, `Ctrl+B` боковую панель). Я это на Windows не проверял. Если сочетание не срабатывает, откройте панель командой (`/palette`, `/sessions`, `/subagents`, `/checks`) или переназначьте клавиши: создайте `state/ui-keys.json`, например `{"sessions": "alt+s", "swarm": "alt+w", "checks": "alt+c", "palette": ["alt+k"]}`. Для каждого действия можно указать список клавиш.

### Инструменты для модели (в чате их вызывает агент)
- `classify_task`: классификация новой задачи.
- `ask_opus`: совет Opus.
- `find_skills`: подбор скиллов из больших библиотек по ключевым словам.
- `subagent`: запуск подагента.

### Скиллы харнеса
- `critic`: независимый аудит изменений перед сдачей: дифф против плана, права доступа (RBAC/IDOR), заглушки, тесты.
- `fullstack-plan`: контракт backend↔frontend перед кодом.
- `ship-pr`: финальная сдача: коммит, rebase на свежую базу, push ветки задачи, черновик PR, проверка SHA на удалённой стороне и статус CI.

## Воркфлоу одной задачи

1. **Классификация.** Первым делом агент вызывает `classify_task`: вид (вопрос, спецификация, код, отладка, ревью, документация, операции); затронуты ли безопасность и обе стороны (backend и frontend); сколько подзадач; режим спецификации; нужны ли скиллы. Пока задача не классифицирована, писать файлы нельзя. Классификацию проверяет Sonnet 5.5: его вердикт главный, а флаг безопасности включается, если его поставил любой из двух. Если Sonnet недоступен, остаётся классификация модели.
2. **Спецификация (`spec`).** Дальше ведёт Opus и пишет только документы, не код. Режим `materials` пишет спеку строго по вашим материалам, `speckit` через spec-kit с нуля.
3. **Фулстек.** Сначала контракт (DTO, схемы, типы полей, коды ошибок и HTTP-статусы, пагинация) в `.pi/context/plan.md`, потом backend и frontend строго по нему. На backend проверка прав на каждый объект и роль, валидация на границе, транзакции для составных записей, никаких секретов в логах. На frontend состояния загрузки, ошибки, пустоты и успеха.
4. **Подагенты.** Если в плане больше трёх подзадач, писать код самому нельзя, пока не вызван `subagent` (см. [Подагенты](#подагенты)).
5. **Автопроверка.** Перед завершением, если изменилось дерево git (кроме правок только документов и картинок), запускаются быстрые типы и линтер для определённого стека (таймаут 5 минут). При ошибке вывод возвращается агенту, до 2 попыток на задачу.
6. **Критик.** Для нетривиальных изменений скилл `critic` делает независимый аудит диффа.
7. **Ревью Opus.** Для крупных (от 60 изменённых строк) или чувствительных изменений (авторизация, сессии, токены, пароли, права, миграции, платежи, крипто, секреты) read-only ревью Opus, до двух раундов. BLOCKER возвращается исполнителю. Для безопасности ревью делает Opus 4.8.
8. **Сдача.** Ветка задачи, rebase на свежую базу, push, черновик PR, проверка SHA на удалённой стороне и статус CI. Агент спрашивает «Мерджить PR #N (…)?» и мерджит только если вы явно ответили да в текущем сообщении.

«Готово» означает проверено: агент обязан показать точные команды и коды возврата, а пропущенные проверки назвать прямо. Порядок гейтов задан порядком расширений в `settings.json`: `ship-gate` должен идти последним.

### Подагенты
Подагенты работают с такими настройками (`extensions/subagent/config.json`, `settings.json`):
- Обязательны, когда в плане больше трёх подзадач. План читается из `.pi/context/plan.md`, `docs/superpowers/plans/*.md` или `docs/plans/*.md` (подзадачи: заголовки `### Task N`, «Шаг N», «Подзадача N» или нумерованные пункты в разделе `## Plan`).
- Для 2-3 подзадач по желанию: если работа разделена на независимые области или нужно ревью со свежим контекстом.
- По одному `worker` на подзадачу, после каждой `reviewer`. Зависимые подзадачи идут по очереди. Параллельно только задачи с непересекающимися файлами: максимум 4 в списке, 2 одновременно.
- Контекст свежий (`defaultSubagentContext: fresh`), глубина вложенности 1, не больше 30 запусков за сессию. Модель подагента `router/auto`.
- Инструменты: `worker` читает, ищет, правит и пишет, thinking выключен; `reviewer` только читает и запускает bash, thinking `high`; `scout` имеет инструменты чтения и записи, thinking выключен.
- Каждый подагент в начале сам подбирает и читает 2 скилла из библиотек, пока он их не прочитал, запись файлов заблокирована.
- Отключены: агенты `claude-code*`, `codex-exec*`, `cursor-agent*`, `researcher`, `evidence-auditor`, расписания, миссии, слэш-команды пакета и лишние функции. Подтверждения пакета (очистка worktree, лимиты, инспектор) выключены, потому что агент по правилам не спрашивает разрешений.
- Агент не должен верить отчётам подагентов: после их работы он сам проверяет `git diff` и запускает проверки.

## Защиты и правила

Из `AGENTS.md` (читается агентом в каждой задаче):
- Решает сам и не спрашивает: разрешений на команды, правки и запуск подагентов не просит. Спрашивает только про необратимое, безопасность, деньги и неоднозначные продуктовые решения.
- Без заглушек: `TODO`, `FIXME`, `XXX`, `NotImplementedError`, пустой `catch {}`, `as any`, `@ts-ignore` запрещены, тесты и линтер не ослабляются и не удаляются.
- Бюджет вывода 16384 токена: правки точечными `edit`, чтение только нужных диапазонов, независимые вызовы одним ходом, связанные проверки одной командой.
- Git: только явные пути в `git add`, без `--no-verify`, без force-push, без push в `main`/`master`, без самостоятельного мерджа; никаких подписей AI и co-author в коммитах.
- Секреты: `.env*` не читаются и не печатаются.
- Локальные правила имеют приоритет: `AGENTS.local.md` в корне проекта и `local/AGENTS.local.md` в папке харнеса перекрывают общий файл.
- Язык: отвечает на языке пользователя, код, идентификаторы и сообщения коммитов на английском.

Расширения-защиты (`ext/`):

| Расширение | Что делает |
|---|---|
| `anti-laziness` | блокирует запись заглушек и обходов типов/линтера |
| `config-guard` | агент не может менять сам харнес (`settings`, `models`, расширения, скиллы, пакеты), читать можно |
| `git-guard` | жёсткие правила git/GitHub: без force-push, без push в базовую ветку, без обхода хуков; мердж только по вашей явной просьбе; просьба с номерами PR (в том числе во вставленном сообщении коллеги) разрешает именно эти PR до конца чата, «не мерджи» отзывает всё; подагенты мерджить не могут вообще |
| `swarm-gate` | обязательные подагенты для больших планов |
| `task-classifier` | классификация и блок записи до неё; после неё же уровень рассуждений по классу задачи (docs/ops/вопросы и сам шаг классификации — без рассуждений, остальные medium/high, потолок — уровень пользователя; на NanoGPT любой уровень выше `off` это один и тот же `:thinking`, экономит только `off`) |
| `output-trim` | длинный вывод `bash` (>9k символов) режется до головы, хвоста и строк с ошибками, полный вывод в temp-файл; работает и у подагентов |

| `fresh-chat` (заметка) | после хода с реальной работой пишет заметку проекта без участия модели (последний отчёт, ветка, коммиты, worktree) в `state/handoff/`; первый запрос нового чата в том же проекте (<48 ч) получает её автоматически |
| `fresh-chat` | авто: после законченной задачи и контекста >40k токенов следующее сообщение открывает новый чат с заметкой (требования, отчёт, git); старый чат в `/resume`. Плюс при >30k агент может сам вызвать `new_chat` |
| `mcp.json` (devtools) | Chrome DevTools MCP (`chrome-devtools-mcp@1.14.0`, headless, изолированный профиль): агент сам открывает страницы, кликает, читает консоль и снимает скриншоты. Семь основных инструментов видны всегда, остальные через `tool_search`. Скриншот читает GLM Flash (роутер отправляет шаг с картинкой из результата инструмента в визуальную цепочку), дальше ход возвращается к DeepSeek. Правила: раздел 7 `AGENTS.md` |
| `auto-verify`, `flow-skills`, `ship-gate` | автопроверка, критик, сдача PR |
| `opus-director` | Opus как директор спецификаций и ревьюер, но не основной кодер |
| `skill-router`, `subagent-skills` | подбор скиллов по требованию из больших библиотек, принудительное чтение двух скиллов подагентами |
| `project-memory` | read-only доступ к памяти проекта из Claude Code: в промпт попадает только индекс (около 1k токенов), файл читается, когда его строка нужна |
| `nanogpt-guard`, `router`, `stream-watchdog` | отказоустойчивость провайдеров (ниже) |

Пакет `cc-safety-net` дополнительно блокирует опасные команды. Блок защиты для агента информация, а не вопрос к пользователю.

## Надёжность провайдеров

- Роутер: таймаут, 5xx, 429, обрыв соединения: один повтор в той же модели, затем модель на 10 минут уходит в сторону и берётся следующая в цепочке.
- Ошибки авторизации и оплаты (401/402/403, неверный ключ, нехватка баланса) `nanogpt-guard` превращает в «provider overloaded», запрос повторяется автоматически, роутер на час отключает провайдера и переводит работу на Gonka.
- Баланс NanoGPT проверяется при старте и раз в 30 минут: меньше $0,50 предупреждение, меньше $0,02 переход на Gonka.
- `stream-watchdog` для Gonka (прокси раздаёт запросы случайным GPU-узлам, и плохой узел виден сразу):
  - **хедж**: если за 8 секунд не пришёл ни один токен, тот же запрос параллельно стартует ещё раз, побеждает первый ответивший;
  - **зависание**: пауза больше 15 секунд после первого токена обрывает поток, запрос повторяется;
  - **медленный поток**: после 30 секунд скорость ниже 10 токенов в секунду на окне 20 секунд тоже обрывается;
  - после 3 подряд обрывов watchdog перестаёт обрывать. Пороги меняются переменными окружения, их список в начале `ext/stream-watchdog.ts`.
- Общие повторы: до 6 попыток, пауза от 1 секунды; таймаут простоя соединения 45 секунд.

## Настройки

Основное из `settings.json`:
- Провайдер и модель по умолчанию `router` и `auto`, thinking по умолчанию `high`.
- Сжатие контекста включено: резерв 150 тысяч токенов, последние 15 тысяч токенов сохраняются.

- Скиллы: заблокирован каталог `~/.agents/skills`, включены `speckit-*` из `~/.claude/skills`.
- Расширения подключены в порядке, от которого зависит порядок гейтов (`ship-gate` последним).

## Экономика на месяц

Исходные данные: средняя задача ≈ 650k входных токенов (около 90% из кэша) и 40k выходных. Цены из таблицы выше.

| Модель | Цена одной такой задачи |
|---|---|
| DeepSeek V4.1 Flash 1017 (основная) | ≈ $0,033 |
| GLM-5.3 Flash | до $0,08 |
| Qwen3 Coder Next | ≈ $0,08 |
| DeepSeek V4 Pro (не включена) | ≈ $0,17 |

Средняя задача с запасом на подагентов, `critic` и повторы: **$0,05–0,08**.

| Нагрузка в месяц | NanoGPT |
|---|---|
| 20 задач | $1–2 |
| 60 задач | $2,5–5 |
| 150 задач | $6–12 |

Anthropic идёт по подписке: фиксированная цена плана без доплаты за токены, но Opus и Sonnet расходуют лимиты плана. Харнес зовёт их только на спецификацию, ревью (максимум 2 раунда), совет (максимум 3) и проверку классификации, а не на каждый шаг.

Практика: держите на балансе NanoGPT $5–10 и пополняйте, когда остаток меньше $3. Оценка сделана по замерам, а не по реальному месяцу работы: после 2–3 недель сверьте с `/journal` (там реальная стоимость каждой задачи по ценам из `models.json`). Тяжёлые режимы (подагенты, `max` thinking, V4 Pro) увеличивают расход в разы.

## Журнал, диагностика, обновления

- Журнал `journal/journal.jsonl`: одна строка на задачу: фрагмент запроса, классификация (и поправил ли её Sonnet), модели, токены, реальная стоимость по `models.json`, длительность, ошибки и повторы, активность защит (автопроверка, критик, вердикт Opus, блоки), вызовы подагентов, ссылки на PR, размер изменений в git, исход. `/problem` добавляет заметку. Журнал локальный и в репозиторий не попадает; его можно отдать Claude, чтобы разобрать проблемы.
- `/doctor` и автоматическая диагностика после обновления Pivot (запускается в фоне, лог `state/doctor.log`, отчёт в `state/diagnostics/*.md`).
- Обновление: `pivot update`. Расширение `watchdog-maintainer` после обновления делает живой тест `stream-watchdog` и при поломке запускает Opus в фоне, чтобы починить только его, не мешая работе.
- Обновление харнеса: повторный запуск скрипта установки или `git pull` в папке харнеса.

## Что не проверено

- Запуск на Windows целиком (`pivot.cmd`, установка пакетов, Git Bash, PATH, `setx`, поведение клавиш во встроенном терминале VS Code).
- Поведение без Claude Code (`skill-router`, `project-memory`, скиллы speckit) и без подписки Anthropic.
- Поведение роутера без `GONKA_API_KEY`.
- Качество работы моделей на реальных больших задачах: замеры скорости и ошибок сняты на синтетических запросах.
- Реальный мердж PR командой агента.
